# HireFlow 人工测试与完整演示流程

本文面向第一次运行项目的测试人员，介绍如何在 Windows 启动系统，分别使用规则演示和兼容模型服务完成从简历到入职的招聘流程。两套资料均为虚构数据。

## 1. 测试范围和准备

本次演示覆盖简历上传与评估、人工确认、三轮面试安排、面试全文总结、待定后的人工反馈、Offer 接受、入职、候选人资料维护与人工审核。面试决定由测试人员确认；模型输出仅供参考。

准备项目源码、PowerShell、Python、Node.js 和 npm。本项目最近一次本地测试使用 Python 3.12.0、Node.js 22.20.0 和 npm 10.9.3。首次安装项目依赖需要访问软件包仓库；如果依赖已经安装，可跳过安装步骤。**本文不需要 Docker。**

在 PowerShell 中确认命令可用：

```powershell
py -3.12 --version
node --version
npm --version
```

以下命令假设项目位于 `D:\ai\workspace\HireFlow-Docker`；如果你的目录不同，请替换路径。使用本机可访问的目录，避免公开使用真实候选人资料。

## 2. 安装依赖并启动后端

打开第一个 PowerShell 窗口：

```powershell
cd 'D:\ai\workspace\HireFlow-Docker\backend'
```

如果还没有 `backend\.venv`，创建虚拟环境；已有环境可跳过：

```powershell
py -3.12 -m venv .venv
```

如果依赖还未安装，执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

先在项目根目录准备配置文件（已有 `.env` 时不要覆盖）：

```powershell
if (-not (Test-Path '..\.env')) { Copy-Item '..\.env.example' '..\.env' }
notepad '..\.env'
```

在文件中设置 `AI_MODE=demo`、`DATA_DIR=./data-manual-demo` 并留空 `HIFLOW_WEBHOOK_URL`，保存。`DATA_DIR` 相对于 `backend` 目录解析；如果希望隔离已有数据，请填写尚未使用的目录。保存后启动：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

保留此窗口，不要关闭。后端会在配置目录创建 SQLite 数据库、工作流检查点及上传文件目录，并补齐虚构的初始候选人和岗位；它们不是下面两套待上传的测试候选人。再次启动会使用同一目录并保留数据；如需全新演示，先停止后端，再把文件中的 `DATA_DIR` 改为另一个未使用的目录。本文不会自动删除数据。

后端直接读取项目根目录 `.env`，不读取同名进程环境变量；修改后需重启后端。`AI_MODE=demo` 只设置服务器默认模式，后面仍可在页面单独选择自定义模型。

打开浏览器访问 `http://127.0.0.1:8000/api/v1/health`，应看到 `ok: true`。如果端口被占用，先检查是否已有后端实例；换端口时也要相应修改前端 Vite 的 `/api` 代理。

## 3. 安装依赖并启动前端

打开**第二个** PowerShell 窗口，运行：

```powershell
cd 'D:\ai\workspace\HireFlow-Docker\frontend'
# 仅首次运行或依赖未安装时执行
npm install
npm run dev
```

保留窗口，按终端显示的地址打开页面，通常为 `http://localhost:5173`。前端会将 `/api` 请求代理到本机 8000 端口。

**检查：**页面出现招聘驾驶舱，左侧可以进入“AI 招聘助手”“简历评估”“候选人管理”和“人工审核中心”。初始候选人可能已显示，这是启动时生成的演示数据。

## 5. 演示一：不使用大模型

### 5.1 上传简历并确认初筛

1. 点击页面右上角“模型设置”，选择“规则演示（无需模型）”，点击“完成”。
2. 打开“AI 招聘助手”。“关联招聘申请”保持空白，点击“上传简历 TXT / PDF / DOCX”，选择林沐安的简历，然后点击“发送”。
3. 系统进入“简历评估”。找到林沐安，核对姓名、岗位和评价，点击“核对并选择”。新建申请时“关联已有申请”保持空白。
4. 在“面试官选择”中选“进入一面”，点击“确认并执行”。

**预期：**评估标记“规则演示 · 非 AI”；候选人管理中出现林沐安的申请，阶段为“一面待安排”。上传和生成参考评价本身不会自动进入一面，必须执行第 4 步。

### 5.2 安排一面并上传全文

1. 在“候选人管理 → 候选人与申请”搜索林沐安，点击该行的“安排面试”。
2. 确认申请、操作为“安排面试”、轮次为“一面”，用日期时间选择器选择 `2026-11-02 10:00`，面试官填“李工”，点击“保存”。
3. 切换到“面试记录”，找到林沐安的一面待进行记录，点击“上传文字”，选择 `面试_林沐安_一面.txt`。
4. 上传完成后，候选人详情会打开。查看面试总结、候选人原话及完整面试文字，再点击“核对并选择处理结果”。
5. 核对姓名、岗位、轮次和总结；为演示待定流程，选择“待定”，点击“确认并执行”。

**预期：**上传全文后阶段仍为“一面待进行”；确认待定后，面试完成，申请进入“一面待反馈”。规则演示会标记非 AI、展示发言和主题，不自动生成能力评分。

### 5.3 待定后推进，完成二面和三面

1. 回到“候选人与申请”，在林沐安行点击“记录反馈”，确认轮次为一面，填写评价 `项目经验与岗位相关，建议推进`，结论选择“通过”，保存。
2. 确认阶段变为“二面待安排”，点击“安排面试”，选择 `2026-11-03 10:00`、面试官“王工”。
3. 在“面试记录”上传林沐安二面全文。查看总结后点击“核对并选择处理结果”，选择“推进”并确认。
4. 按同样方式安排三面：`2026-11-04 10:00`、面试官“赵工”；上传三面全文，核对后选择“推进”。

**预期：**一面人工通过后，一面评估关联结果同步为“推进”；二面通过后进入“三面待安排”；三面通过后进入“Offer待处理”。面试记录保留每轮的全文和结论。

### 5.4 完成 Offer 和入职

在“候选人与申请”的林沐安行，依次点击“确认接受 Offer”和“确认入职”，分别在弹窗中确认。

**预期：**阶段依次变为“Offer已接受”和“已入职”。点击“详情”可查看候选人资料、简历、三轮面试和招聘事件时间线。

## 6. 演示二：使用模型服务

### 6.1 检查模型服务

准备服务商提供的模型名称、OpenAI 兼容接口地址和所需 API Key。该项目当前支持兼容 Chat Completions 的服务；使用其他原生协议时需要相应适配。地址由后端访问，必须对后端所在机器可达；远程接口携带 Key 时必须使用 HTTPS。

在页面“模型设置”选择“自定义模型”，填写服务商提供的名称、接口地址和 Key；无需认证时 Key 可留空。点击“测试模型连接”，等待结果显示“连接成功”，再点击“完成”。连接测试会发送简短生成请求；它不能保证模型一定满足后续 JSON 输出和长文本要求。自定义设置只保存在当前页面内存，刷新后需要重新填写；不要把密钥写进演示资料。

### 6.2 运行模型流程

重复第 5 节的操作，但使用**周予安**的简历与三轮全文，并使用第 4 节的 15:00 面试时间。为保证两套数据互不混淆，新建简历申请时保持“关联招聘申请”和“关联已有申请”为空，上传面试全文前核对候选人和轮次。

1. 上传简历，查看模型评价；修正必要信息后选择“进入一面”。
2. 依次安排一、二、三面并上传对应全文。每轮核对总结后选择“推进”；也可在一面先选择“待定”，再从“记录反馈”人工通过。
3. 三面后依次确认接受 Offer 和入职。

**预期：**简历和面试结果显示所选模型名称；面试总结提供具体表现、建议以及可能出现的 1～5 分维度评分。评分有逐字稿依据才显示分数；内容、分数和耗时会因模型和服务而异。评估失败时检查服务商的接口兼容性、模型能力、JSON 输出和上下文限制。

## 7. 补充功能和异常检查

### 人工创建与维护候选人

1. 在“候选人管理”点击“新建候选人 / 申请”，填写一个新的虚构姓名、岗位、技能和负责人，保存。
2. 该行点击“简历”，可上传 TXT/PDF/DOCX，或填写文字并点击“保存文字简历”；点击“详情”检查简历可查看和下载。
3. 点击“编辑”修改资料并保存；在“初筛”中填写评价，选择“进入一面”后保存。

**预期：**人工建档和初筛无需大模型。新申请初始处于简历筛选阶段；确认进入一面后变为一面待安排。

### 人工审核

1. 将模型设置切回“规则演示”。在“AI 招聘助手”中选择一个已有申请，在消息框输入 `你好` 并发送。
2. 检查消息是否提示无法识别操作、转入人工审核。打开“人工审核中心”，找到该任务。
3. 将“招聘操作”改为“查询招聘状态”，确认关联申请正确，点击“确认并执行”。

**预期：**系统返回当前招聘阶段；查询不会推进招聘流程。审核也可选择“拒绝操作”。

### 结果检查

- “招聘驾驶舱”统计应反映申请和阶段变化；“候选人管理 → 详情”应展示三轮面试、相应全文及事件。
- 面试完成或当前阶段不再是该轮待进行时，不再允许上传该轮新全文。
- 没有配置 HiFlow Webhook 时，“事件同步状态”显示未配置和待同步；这不代表事件已发送到外部表格。
- 不要重复确认已结束的简历或面试评估；若要从头重演，停止后端并按第 2 节创建新的测试数据目录，避免覆盖原数据。

## 8. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 前端无法加载或请求失败 | 确认两个终端仍在运行，访问后端健康接口，检查 5173/8000 端口及 Vite 代理。 |
| 看不到“上传文字” | 先安排对应轮次；只有当前轮次待进行且面试状态为待进行时才显示上传入口。 |
| 关联申请或候选人不一致 | 新建简历时清空关联申请；上传面试全文时选择相同候选人、岗位和轮次，必要时人工修正。 |
| 模型连接失败或超时 | 使用页面“测试模型连接”，检查服务商的接口地址、模型名称、权限、网络和服务日志。 |
| 规则演示没有评分 | 属于预期行为；评分是模型参考结果，人工可在核对时添加有依据的维度。 |
| `.env` 设置未生效 | 确认编辑的是项目根目录 `.env`，保存后重启后端；程序不会使用同名进程环境变量覆盖文件配置。 |

## 9. 收尾与可选自动检查

在两个运行窗口分别按 `Ctrl+C` 停止前端和后端。停止服务不会删除第 2 节创建的本地数据库和上传文件；如需保留演示结果，请保存该目录。

可在项目根目录执行以下**可选**命令，自动用临时数据库跑规则模式；脚本不会修改页面正在使用的数据库：

```powershell
.\backend\.venv\Scripts\python.exe scripts\simulate_recruitment.py
```

运行模型模式前，在项目 `.env` 或另一份配置文件中填写 `MODEL_NAME`、`MODEL_BASE_URL` 和可选的 `MODEL_API_KEY`，再运行 `--mode model --model-config <配置文件路径>`；`--mode both` 可顺序测试两种模式。密钥不要写在命令行。该脚本用于辅助验证，不能替代本说明中的人工页面检查。
